## Cause

`SbxSandbox.exec` started the watchdog through `setsid sh -c ...`.
`sbx exec` makes its process a process group leader, and `setsid` forks when called from a leader.
The parent exits at once with code 0, and the command keeps running without the exec process.
`sandboxd` waits half a minute for the exec's stdout and stderr to drain, then cuts them off.
So any command longer than about 35-40 s lost its output, `sbx exec` exited with code 0, and the exit code file never appeared.

In the `sbx` `daemon.log` it looks like this:

```
11:04:00.305 task exit emitted        exit_status 0      (6 ms after start)
11:04:30.307 timed out waiting for IO drain after wait
11:04:40.315 POST /sandbox/.../exec/attach 101 40017
```

No test caught this.
The fake `sbx` ran `setsid` itself and waited for the command, and the contract tests ran only commands shorter than half a minute.
The first self run on 2026-10-22 came before `SbxSandbox`.

Reproduction on the real `sbx`: `SbxSandbox.exec` with `sh -c 'echo start; sleep 45; echo done'` gives `SandboxLost` after 43 s, with only `start` in the log.
With `setsid -w` the same command exits with code 0 after 47 s, and `done` is in the log.

## Fix

- `SbxSandbox.exec` starts the watchdog through `setsid -w`, and exec waits for it to finish.
- The fake `sbx` behaves like the real `setsid` of a group leader: without `-w` exec exits at once with code 0, and the command keeps running.
- The contract test `test_command_that_outlives_the_io_drain_timeout_keeps_its_output_and_exit_code` runs a 45 s command on the real `sbx`.

## What the engine is missing

- Pipeline `self` does not set `attempts`, so the Stage gets the built-in value 1.
  A single lost Attempt sends the Ticket straight to `abandoned`, even though the Sandbox is at fault.
  A lost Probe does not spend a Gate attempt (#53), but a lost Attempt does.
- An abandoned Ticket leaves its stopped Sandbox behind, and `sbx ls` shows it until the owner deletes it by hand.
